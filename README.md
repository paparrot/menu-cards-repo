# Карточки меню: учим состав блюд

Статическое веб-приложение (без сервера и сборщиков) для изучения состава блюд меню «осень–зима 2026–2027».
Карточки, самопроверка ввода ингредиентов, свайпы, озвучка, фото, рецепты и выход блюд, прогресс на устройстве.

## Быстрый старт

```bash
python3 -m http.server 8000      # или: npm run serve
# открыть http://localhost:8000
```

`index.html` можно открыть и просто двойным кликом (`file://`): все скрипты подключаются обычными `<script>`.

## Структура

```
index.html            разметка (меню-шторка, область карточки)
css/style.css         стили, светлая и тёмная темы, адаптив (телефон / планшет)
js/app.js             вся логика приложения (без зависимостей)
data/cards.js         ГЕНЕРИРУЕТСЯ: const DATA (карточки) и const IMGS (пути к фото)
images/001.jpg …      ГЕНЕРИРУЮТСЯ: фото блюд из таблицы
source/               исходники: menu.md (меню) и xlsx с рецептами (xlsx ~39 МБ, в архив не входит: положите его сюда сами)
tools/build_data.py   source/ -> data/cards.js + images/
tools/bundle.py       всё -> один файл dist/menu-cards.html
tests/smoke.js        дымовой тест в jsdom
```

## Обновление меню

1. Замените `source/menu.md` и/или положите таблицу как `source/menu-autumn-winter-2026-2027.xlsx` (или укажите путь через `--xlsx`).
   Файл весит около 39 МБ из-за встроенных фото: хранить его в git лучше через Git LFS или отдельно от репозитория.
2. Пересоберите данные:
   ```bash
   pip install -r requirements.txt   # openpyxl, Pillow
   python3 tools/build_data.py
   ```
   Скрипт напечатает, сколько карточек, фото, рецептов и выходов получилось, и перечислит блюда меню, которых не нашёл в таблице.

Как собираются данные:
- Карточки берутся **только** из `menu.md`: `## Раздел`, строка без дефиса = блюдо, `- ингредиент`, вложенный `\t- пункт` или скобки = состав заготовки.
- Из таблицы к карточке подтягиваются фото, рецепт и выход. Блюдо ищется по названию (с приоритетом листа своего раздела). Если в таблице чего-то нет, поле остаётся пустым, ничего не выдумывается.
- У десертов в таблице описание, а не рецепт, поэтому рецепт для них не заполняется.
- Блюда из таблицы, которых нет в меню, игнорируются.

Формат карточки в `DATA`: `{s: раздел, d: блюдо, i: [{n: ингредиент, p: [состав заготовки]}], y: выход, r: рецепт, im: индекс в IMGS}`.
Поля `y`, `r`, `im` необязательны.

## Один файл

```bash
python3 tools/bundle.py     # -> dist/menu-cards.html (≈4,5 МБ: CSS, JS, данные и фото внутри)
```

Такой файл можно выложить на любой статический хостинг (GitHub Pages, Netlify, Cloudflare Pages) или открыть офлайн.
Единственный внешний ресурс: шрифты Google Fonts (без них работают системные).

## Тесты

```bash
npm install
npm test               # проверяет index.html
npm run test:dist      # проверяет собранный dist/menu-cards.html
```

Тест проходит основной сценарий: проверка ингредиента, переворот, отметки на обороте, свайп, двойное нажатие, меню-шторка, экспорт и импорт.

## Где хранится прогресс

В браузере устройства (данные привязаны к адресу сайта):
- `localStorage`: `menu-cards-known-v1` (блюда с «Знаю»), `menu-cards-ing-v1` (отмеченные ингредиенты);
- IndexedDB `menu-cards`: зеркальная копия, из которой прогресс восстанавливается, если localStorage очистили;
- при запуске запрашивается постоянное хранилище (`navigator.storage.persist()`).

Прогресс не синхронизируется между устройствами. Для переноса есть экспорт и импорт в меню приложения (JSON-файл или текст).
Если сменить название блюда в `menu.md`, отметка у этой карточки сбросится: прогресс привязан к названию.
